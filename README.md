# 智能人形机器人自主巡线控制系统

> STM32F103ZET6 · C · SPL · USART · I²C · ST3215 · OpenMV · 关键帧动作调度

华为终端硬件精英挑战赛 2026 华中赛区决赛项目。本项目面向 19 自由度人形机器人封闭跑道任务，使用 STM32F103ZET6 协调 19 路串行总线舵机、左右两块 8 通道灰度模块、OpenMV 和扫码枪，完成巡线、弯道修正、障碍识别、扫码动作与整圈返回起点测试。其中 ID 1–18 驱动躯干及四肢，ID 19 驱动搭载扫码枪的头部转向轴。

## 项目亮点

- **单总线 19 路舵机控制：** 19 个串行总线舵机共享 1 Mbps 单线半双工总线，以 ID 1–19 区分节点。
- **18 路步态关节同步下发：** 对 ID 1–18 使用 `0x83` 广播同步写，一帧下发 18 路关节的 2 字节目标位置；完整帧 62 Byte，在 UART 8N1 下理论线路时间约 0.62 ms。
- **第 19 路头部转向：** 对 ID `0x13`（十进制 19）使用普通位置写指令，驱动头部扫码枪在两个目标位置间转动；扫码枪本体通过独立串口传回数据。
- **双路灰度巡线：** 两块 8 通道灰度模块共用 I²C1，通过 `0x4C`、`0x4E` 两个地址读取左右各 8 bit 数字位图。
- **多外设协同：** USART1 接入 OpenMV，USART2 接入扫码枪，结合灰度判决和关键帧动作调度构成“感知—决策—执行”链路。

## 关键实现

### 1. 18 路步态舵机同步写

每个 ST3215 在共享总线上具有独立 ID。控制器使用广播 ID `0xFE` 和同步写指令 `0x83`，将 18 路目标位置放入同一数据帧：

```text
FF FF FE 3A 83 2A 02
│     │  │  │  │  └─ 每个舵机写入 2 Byte 目标位置
│     │  │  │  └──── 目标位置首地址 0x2A
│     │  │  └─────── SYNC WRITE 0x83
│     │  └────────── 长度字段 0x3A = 58
│     └───────────── 广播 ID 0xFE
└────────────────── 帧头

随后为 18 组 [舵机 ID + 位置低字节 + 位置高字节]，最后 1 Byte 校验和。
```

长度字段计算：

```text
Length = (单舵机数据长度 + ID长度) × 舵机数 + 4
       = (2 + 1) × 18 + 4
       = 58 = 0x3A

完整帧长度 = Length + 帧头2 Byte + ID 1 Byte + Length字段1 Byte
           = 58 + 4
           = 62 Byte
```

UART 8N1 每字节在线路上占 10 bit，因此理论线路发送时间为：

```text
62 Byte × 10 bit / 1,000,000 bit/s = 0.62 ms
```

作为对照，如果对 18 个舵机逐个发送仅包含 2 字节位置的普通写帧，理论数据量约为 `18 × 9 = 162 Byte`，线路时间约 1.62 ms。同步写减少了总线数据量以及不同关节接收目标指令的时间差。

> **说明：** 0.62 ms 只对应 ID 1–18 的 62 Byte 同步写帧，表示理想波特率下从首个起始位到末个停止位的理论线路时间。它不包含第 19 路头部舵机的独立报文，也不包含 MCU 组帧、半双工方向切换、舵机协议解析、内部控制周期和机械响应，不能表述为实测关节启动误差。

### 2. 第 19 路头部舵机与扫码动作

头部舵机与 18 路步态舵机共用舵机总线，但不加入步态同步写帧。程序使用 ID `0x13` 对其单独写入目标位置：

```text
FF FF 13 05 03 2A 03 44 73   # 动作 76：头部位置 1
FF FF 13 05 03 2A 04 00 B6   # 动作 77：头部位置 2
      │     │  │
      │     │  └─ 目标位置寄存器 0x2A
      │     └──── WRITE 指令 0x03
      └────────── 舵机 ID 0x13（十进制 19）
```

扫码枪识别到数字 `6` 后，通信管理器将其映射为动作码 `76`。主循环随后交替执行 `76` 和 `77`，使头部舵机带动扫码枪往复转向。这里的“头部舵机连接扫码枪”是机械安装关系：舵机负责改变扫码枪朝向，扫码数据仍通过 USART2 独立接收。

```text
扫码数据“6” → 动作码 76 → 76/77 交替执行
                              ↓
                    ID 19 头部舵机往复转向
```

### 3. 双路灰度巡线

左右两块灰度模块共用 I²C1。主控分别读取地址 `0x4C` 和 `0x4E` 的数字模式数据，每块模块返回 1 Byte 位图，每一位对应一路探头的黑白状态。

```text
左侧位图 Digtal_L：bit0 ... bit7
右侧位图 Digtal_R：bit0 ... bit7
                         ↓
          黑线覆盖位置与左右状态判决
                         ↓
             微调 / 中调 / 大调动作码
```

这种设计只占用一条 I²C 总线，通过不同设备地址区分左右模块，并利用两侧检测结果处理直道、弯道和局部丢线场景。

### 4. 关键帧动作与多源任务联动

步态以原始舵机同步写帧保存，动作表记录数据指针、帧长度和帧间延时。`run_action_code()` 将巡线、视觉或扫码产生的动作码映射为关键帧序列，再由 `play_frames()` 依次发送。

```text
灰度 / OpenMV / 扫码数据
          ↓
      动作码判决
          ↓
   run_action_code()
          ↓
     play_frames()
          ↓
  ├─ 0x83 同步写 → ID 1–18 步态舵机
  └─ 0x03 独立写 → ID 19 头部舵机
```
